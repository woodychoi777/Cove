# GitHub 게시 준비 — v0.1.19

공개 저장소는 [woodychoi777/Cove](https://github.com/woodychoi777/Cove)입니다. 이 문서는 공개 파일 선별과 릴리스 재현 절차를 설명합니다. Windows 설치 후보는 실기기 검증 전이며 공개 릴리스에 이 한계를 명시해야 합니다.

## 공개 소스와 설치 파일

`npm run public:prepare`는 제품 코드·합성 검사·공개 문서·CI만 `dist/cove-public-source`로 복사합니다. 공개 파일 목록은 `dist/PUBLIC_FILES.txt`, 개인정보/경로 검사 결과는 `dist/PUBLIC_SCAN.json`입니다. 실제 음악, 서재 DB와 백업, 개인 기록, 프로필, 내부 UX/품질 작업 문서와 실제 서재 화면 캡처는 공개 대상에 포함하지 않습니다.

원래 프로젝트 폴더에서 전체 파일을 그대로 올리지 마세요. 공개 후보 폴더나 `Cove-0.1.19-source.zip`의 소스만 새 저장소로 사용하세요. 공개 대상은 검토된 소스와 설치 파일이며 개인 서재와 개발 프로필은 제외합니다.

설치 파일은 Git 소스에 커밋하지 않고 GitHub Releases의 첨부 파일로 올립니다.

- `Cove-Setup-0.1.19-x64.exe` — Windows 10/11 x64 설치 후보, 미서명·실기기 미검증
- `Cove-0.1.19-windows-x64.zip` — 폴더 전체를 풀어 실행하는 Windows 후보
- `Cove-0.1.19-mac-arm64.dmg` — Apple Silicon Mac, ad-hoc 서명·Apple 공증 없음
- `Cove-0.1.19-source.zip` — 선별한 MIT 소스와 의존성 고지
- `SHA256SUMS.txt` — 제공 파일 검증용 해시

## 게시 순서

1. 공개 후보 파일 목록과 README·라이선스를 최종 검토합니다. 기존 개인 작업 폴더의 Git 기록/설정은 복사하지 않습니다.
2. GitHub에서 새 저장소를 만들고 검토한 공개 후보 소스만 커밋합니다. 개인 이메일 공개 여부를 확인하고 원한다면 GitHub의 확인된 비공개 이메일을 사용합니다.
3. Checks and Windows package 워크플로가 통과하는지 확인합니다. 워크플로는 읽기 권한만 사용하고 실제 릴리스 게시 작업은 하지 않습니다.
4. Windows에서 설치·재생·업데이트·제거 후 보존을 [확인 절차](WINDOWS.md)대로 검사합니다. GitHub runner 자동 검사는 실제 스피커·헤드폰·기기 잠자기 검증을 대신하지 않습니다.
5. v0.1.19 태그의 릴리스를 작성합니다. Windows 실기기 검증이 끝나기 전에는 **Pre-release**로 표시하고, 아래 공개용 릴리스 문구와 현재 확인 범위를 사용합니다.
6. 설치 파일과 해시를 Releases에 첨부합니다. API 키나 개인 파일·DB·원래 서재 스크린샷을 첨부하지 않습니다.

## 릴리스 문구 초안

Cove는 음악 파일·가사·개인 코멘트를 로컬에 간직하는 음악 서재입니다.

- 파일·폴더·드래그로 복사 추가, 필요할 때 곡명·가수명 일괄 확인/수정
- 폴더 형식에 구애받지 않는 자동 추가, 중복·원본 보존과 오류 복구
- Collection 플레이리스트·연속 재생·셔플·반복·대기열
- 현재 줄을 따라가는 가사와 버튼 아래의 작은 코멘트 팝오버
- 시스템/수동 밝기, 넓은 설정, 로컬 기록 내보내기

Mac은 Apple Silicon 전용이며 로컬 ad-hoc 서명입니다. Apple 공증을 받지 않았습니다. Windows x64 설치/포터블 파일은 빌드와 구조 검사를 완료했으나 실기기 설치·재생은 아직 확인하지 않은 후보입니다. Windows 알람은 앱 실행 중에 동작하며 잠자기 깨우기를 지원하지 않습니다. 새로고침·재실행 후에는 자동 재생하지 않습니다. 업데이트/제거에서 사용자 서재와 프로필을 보존합니다.

Cove 소스는 MIT 라이선스이며 Electron·음원 분석 의존성·NSIS의 개별 고지가 함께 제공됩니다. 음악은 포함하지 않습니다.
